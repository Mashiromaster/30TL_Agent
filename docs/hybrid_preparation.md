# 混合研究准备链路与本地验收

更新：2026-10-04（Asia/Shanghai）。这是 [混合决策框架](hybrid_decision_research_2026-10-03.md) 的第二阶段交付，不是实盘上线说明。LightGBM 给基础数值判断，Jev 做受限语义判断和路由，LLM Researcher / Advisor 给可追溯的研究意见；新链路补齐它们之前的数据与模型准备环节。

## 1. 本次解决的问题

架构审计确认，原缓存不能直接用于新模型验收：

- 旧 `mc_ex.py` 用当天最后一条持仓量决定当天所有分钟的主力合约，含日内前视信息。
- 旧因子 159,465 行，215 列，包含 64 个没有训练折内来源证明的 CNN 特征，不能因文件存在就视为可用。
- 原始分钟、旧拼接行情和生产因子均截至 2026-06-02。日线缓存更新到 9 月不能补成真实分钟行情。
- 旧因子有 751 个观测日期，但只有 620 日能产生有效 30-bar 标签；数据覆盖不能按日历跨度估计。
- 只有 legacy 模型 pickle，没有合格的 managed release。既有训练入口兼具发布行为，不适合“先看看候选效果”。

本次保留旧文件与兼容入口，新工作台走独立候选路径。没有直接覆盖旧主力拼接或旧因子，没有以放宽新鲜度、加载 legacy 模型、缩短封存集来消除阻断。

## 2. 阶段与写入权限

| 阶段 | 输入 / 输出 | 边界 |
| --- | --- | --- |
| 就绪检查 | 因子文件、构建清单、managed model → 内存 JSON | 只读；检查时间、标签、来源、特征和策略指纹，不训练或预测 |
| 因果候选构建 | 本地原始 TL 分钟 → `artifacts/factor_candidates/local-<uuid>/` | 不联网，不覆盖原始/生产文件，不刷新行情 |
| 独立候选训练 | 已验证因子 → `artifacts/experiments/train-<id>/` | 固定输入副本与 SHA256，默认双线程；不发布 |
| 混合研究 | 明确选定的因子 + 已发布模型 + 时点证据 → `outputs/hybrid_runs/` | 模型候选不自动启用；默认离线、研究输出不能下单 |
| 正式发布 | 人工审阅通过门禁的候选及适用范围 | 独立步骤；本次未执行，也没有在新页面提供一键激活 |

核心实现：`research_readiness.py`、`factor_candidates.py`、`LightGBM_model.train_candidate`、`hybrid_runtime.py`、`hybrid_dashboard.py`。

### 因子候选的构建契约

1. 原始价格、成交量、持仓量、时间和合约身份必须有效，拒绝重复与越界 OHLC；只收 TL 季月合约。
2. 只用上一观测日的收盘持仓量确定下一观测日合约；缺少可用前日信息则隔离，不能回看当天收盘决定当天合约。
3. 当前日不视为完整历史日。基于现有本地时间戳约定，只接纳 09:31–11:30、13:01–15:15 的 255 条分钟完整模板；不合格日逐条写入隔离审计。
4. 仅重建市场因子。Tick、基差、文本、CNN、GP 不从旧缓存继承；宏观缓存只有具备可用时间、历史修订核验及绑定哈希时才接纳。当前宏观缓存未通过，明确排除。
5. 前向拼接调整价以换约首 bar 零收益连接；这只是研究合成序列，不是可执行的换约盈亏。
6. 保存输入哈希、因子哈希、算法契约、覆盖范围、排除来源及已知限制；运行时核验 manifest、DataFrame attrs 和实际加载字节的 SHA256 一致。源文件替换或摘要不符则拒绝。

**本地构建契约已核验不等于完整 PIT 认证。** 原始数据供应商、历史修订 vintage 与交易所日历仍未认证；缺失观测日期不能区分假期和缺数。复用的旧因子窗口以行数定义，存在“240 bar ≈ 1D”命名以及长窗口初始化填零：当前前 9,500 行仍位于最长窗口预热范围内。以上限制随清单公开，不能被 UI 的成功提示掩盖。

### 候选训练与门禁

- 收益标签：下一 bar 入场、30-bar 持有，禁止跨日和跨合约标签；时间分区带 purge。
- 分区：训练最少 120 个有效日期，验证及封存各 60 日；训练回看 9×30 个自然日。就绪检查只统计标签有效样本，不把稀疏日期充数。
- scaler、特征分组及模型训练只使用训练集；模型选择用验证集；封存集只评估已选模型并进行发布否决。
- 复用既有 validation 稳定性、正 holdout IC、含成本策略收益 / Sharpe / 回撤门禁，新增输入未改变及来源契约门禁。三个策略阈值在训练开始前校验并固定，只能收紧基线，拒绝 NaN、Inf 与非法类型；评估 JSON 禁止非有限数值。
- `train_candidate` 默认 `thread_limit=2`，限制 LightGBM、分层微观模型、可选 GP 与原生线程池。当前实测 GP 未开启。
- 无论门禁成功或失败都不调用 `ReleaseManager.promote`；失败不覆盖旧成功结果，候选状态明确区分 `candidate_ready`、`candidate_rejected` 与 `failed`。
- 输入及输出路径约束在本项目指定目录，拒绝符号链接重定向。文件存在、清单可读、训练资格、候选验收和生产发布是不同状态。

历史样本过期不会阻止离线候选研究，但会阻止当前研究就绪；`training.eligible=true` **不是**生产发布认证。自然时钟 24 小时新鲜度检查仍是保守基线，并未接交易所节假日日历。

`--as-of` 约束行情与证据可见时点，但仍使用当前已发布模型；尚未实现“当时已经发布的模型版本”回放，不能当成无前视交易回测。

## 3. 使用方式

前端：[本地工作台](http://127.0.0.1:8503/)，进入「混合决策工作台 → 数据与模型准备」。

1. 点击「检查数据与模型就绪状态（只读）」了解生产输入的真实阻断。
2. 已有候选时，点击「读取已保存因子候选」；否则点击「构建本地因果因子候选」。读取最多 30 个小清单，不反序列化因子，不自动构建或训练。
3. 在「研究因子来源」显式选择候选，再次检查。顶部仍标注为生产预览，不混成候选预览。
4. 需要新实验时，确认本地计算范围后启动独立候选训练。训练前重新检查资格和哈希，避免使用过期检查结果。不要为了改变一次不合格结果，反复试探相同封存集。
5. 研究运行使用选定因子及已发布模型；没有合格 release 时保留阻断。候选训练不会偷偷激活模型。

CLI 在仓库根目录运行，以下模式 stdout 是单个 JSON，日志走 stderr；**没有 `--json` 参数**：

```bash
# 只读诊断现有生产输入
.venv/bin/python src/main.py --mode readiness

# 显式构建隔离候选（返回新 factor_path）
.venv/bin/python src/main.py --mode prepare-factors

# 把 <candidate-id> 替换为上一步返回的真实 ID
.venv/bin/python src/main.py --mode readiness \
  --factor-path artifacts/factor_candidates/<candidate-id>/factors.pkl

# 独立训练，不发布；必须通过来源和标签资格检查
.venv/bin/python src/main.py --mode train-candidate \
  --factor-path artifacts/factor_candidates/<candidate-id>/factors.pkl

# 不保存研究报告的离线诊断
.venv/bin/python src/main.py --mode hybrid --network-mode offline --no-persist \
  --factor-path artifacts/factor_candidates/<candidate-id>/factors.pkl
```

不要将既有 `--mode train` 与 `train-candidate` 混淆：前者仍是旧构建及发布工作流，后者始终只产出候选。准备模式拒绝在线、通知、watch、隐式重建等冲突参数。候选产物必须落盘，不能与 `--no-persist` 合用；因子路径只允许项目内生产文件或候选目录。

pickle 是受信任的本地内部格式，不是上传入口；不要把陌生文件放入这些目录后加载。Python API 的 factors/runtime/adapters/evidence_loader/clock 注入是受信任测试与集成接口，不是执行任意 Python 代码的沙箱。报告 `integration.injected_components` 记录这些替换；生产 UI/CLI 不传测试对象，不把注入结果作为生产验收。

## 5. 下一阶段优先级

1. **先补数据**：选定有授权的 TL 合约分钟数据源，补齐 2025 年末以来的缺口，保留 provider、取得时间、修订版本和交易日历；不把第三方日线“加工成分钟”。
2. **再修研究定义**：统一行数窗口与交易日定义、完整预热处理、换约与成本仿真，建立不同时间区间的稳定性评估。
3. **再接宏观和文本**：补充可核验发布时间与历史 vintage；CNN/GP 只在训练折内拟合；语义特征用严格时点可用性和独立增量评估。
4. **重新设立未使用的封存期**：本次封存结果已经读取，后续研究不能继续把它当从未看过的最终测试集。走滚动验证与新的最终封存，必要时等待新增真实数据。
5. **最后做在线 smoke 与人工发布**：需要明确启用外部服务及其数据外发范围；费用、时延和有限故障测试单独验收。任何金融执行另行设计券商授权与风控，不从研究页面隐式升级。

视频完整内容及对应开源仓库仍未取得，本轮不是视频源码复刻；其证据边界沿用调研文档。
