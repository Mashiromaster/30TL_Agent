# 行情口径与数据质量边界

## 本次修复解决什么

原行情页把主力连续代码（例如 `TL0`）根据最后持仓量猜成某个具体合约，又与旧合约分钟数据合并；日 K 还只从分钟 `close` 列生成开高低收。这样会同时产生合约身份错误、历史断档和价格极值丢失。刷新到最新的一根分钟线不代表中间的历史完整。

修复后，行情身份由**请求代码**决定，绝不由持仓量决定：

| 序列 | 身份与用途 | 不应如何使用 |
| --- | --- | --- |
| `TL0`、`T0`、`TF0`、`TS0` | 第三方主力连续序列，`series_kind=continuous` | 不冒充某个年月合约，不写入合约级训练原始文件 |
| `TL2612` 等明确合约 | 指定交割年月的具体合约，`series_kind=contract` | 不按每分钟最大持仓量与其它合约交替拼接 |
| 原训练分钟文件 | 保留此前历史记录及新的明确合约分钟记录 | 未经审计，不应把旧标签视为可靠来源证明 |

每次新抓取保存 `ticker`、`source_symbol`、`series_kind` 和 `source`。前两个代码均保留真实请求值。默认合约候选按当前季度滚动生成，而不是固定写死年月；候选只是请求列表，不保证全部上市、均有响应或其中某个就是主力。源为空或报错会明确记录，不猜测补齐。

## 日 K 与分钟 K 分开

- 日 K 读取对应代码的**日线接口**，不再用近期有限分钟窗口假装覆盖完整历史日 K。
- 分钟接口只提供有限的近期窗口。可用分钟线按 `open:first / high:max / low:min / close:last / volume:sum` 聚合；不再仅从收盘价推导 OHLC。
- 不混合不同代码计算一根 K 线。日线缓存和分钟缓存相互独立。
- 主力连续本身可能发生换月及价差跳变。它不是稳定持仓合约，也不等同于经过后复权的可交易回报序列。
- 当日数据可能仍在形成；最新观测时间不是全区间完整性保证，也不是交易所确认的实时性承诺。
- 页面会区分数据来源、实际覆盖窗口和刷新失败；覆盖不足应保留告警，不能通过插值或压缩横轴制造完整历史。

## 新缓存不覆盖旧训练数据

页面的行情服务使用独立的行情缓存，按请求代码和频率隔离。网络失败时可回退已有缓存，但必须保留错误与缓存状态，不能把“有缓存”宣称为“刷新成功”。只刷新日线不会触碰 `data/TL分钟级量价数据.pkl` 等原始文件。

训练分钟更新脚本 `src/update_market_data.py` 仅接受明确季度合约。更新前对已有原始文件做字节级备份（同目录 `原文件名.bak.<时间>-<随机标识>`），新数据先完整序列化到同目录临时文件、刷新后，再进行原子替换。序列化、备份或替换失败时不覆盖旧文件。备份不会自动删除，可用于人工恢复。

合并键保持为 `date + ticker`；同一明确合约、同一分钟的成功新观测可替换旧观测，其他历史记录保留。单个源失败不会丢弃其它合约成功返回的数据，控制台会列出失败合约；所有合约均失败时不写文件。请避免并发运行多个写同一原始文件的更新进程。

为兼容既有下游，保留旧的 `money = close * volume * 100` 估算式，并为新记录附加 `money_estimated=True`、`money_method=legacy_close_x_volume_x_100`。**该字段不是交易所报告的真实成交额**，不能用于成交额精度判断；本次没有顺带修改因子或交易计算口径，行情图也不使用该估算金额。

## 安全的使用方式

在仓库根目录执行，下列命令会按其用途写入行情缓存；不是只读诊断：

```bash
# 只更新 TL0 主力连续日线的独立行情缓存，不修改训练原始分钟文件。
.venv/bin/python src/update_market_data.py --variety TL --daily-only

# 仅更新明确指定的具体合约分钟。代码是示例，执行前确认目标合约。
.venv/bin/python src/update_market_data.py --variety TL --symbols TL2612 TL2703

# 按当前季度生成候选列表并逐源更新；失败合约明确报告。
.venv/bin/python src/update_market_data.py --variety TL

# 兼容指定项目根目录。
.venv/bin/python src/update_market_data.py --variety TF --base-dir /absolute/project/path
```

`--symbols` 支持空格或逗号分隔；拒绝 `TL0` 等连续代码及跨品种代码。`--daily-only` 与 `--symbols` 不可并用。脚本默认根目录由其自身位置推导，不再固定到某台 Windows 电脑的桌面路径。所有合约失败、日线刷新失败或写入失败会返回非零退出码；部分合约成功时保存成功部分并显示失败清单，不能据此认定整批覆盖完整。

## 历史数据需要单独审计

这次修复不重写、重新标记或自动删除旧缓存。此前被 OI 猜测污染的记录无法仅凭现有标签安全纠正。应先保留快照，再用能明确识别具体合约的可信历史源，按 `date + ticker` 对账：

1. 检查原请求代码、时间、OHLC、量和持仓量；没有原请求证据时标记来源未核验，不猜改为另一个合约。
2. 按合约/交易日统计分钟覆盖；结合交易所交易日历、上市与到期区间、日内交易时段解释缺口。工作日不必然是交易日。
3. 对照同代码的独立日线或交易所数据，核验 OHLC 极值、成交量和日期边界；确认交易量单位及更新时间差异。
4. 得到可追溯的历史分钟后才能重建、重新训练或回测；不能凭最近分钟窗口补回几个月前的缺失记录。

## 不包含的保证

本次修复的是代码层的序列身份、聚合和缓存隔离错误，并增加可见失败边界。第三方免费行情仍可能延迟、缺失、改版或本身错误；没有宣称已与中金所全历史独立对账，也没有把它升级为有服务保证的实盘交易行情源。实盘执行应另接有授权、稳定性和明确时延保证的券商或行情服务，并保持风控与研究页面隔离。

## 回归检查

```bash
.venv/bin/python -m pytest tests/test_market_data.py tests/test_market_dashboard.py tests/test_update_market_data.py -q
```

离线测试覆盖连续/具体合约身份、OHLC 聚合、缓存隔离、逐源失败、旧数据保留、备份以及原子替换失败。测试写入只使用临时目录，不会更新现有原始训练行情文件。测试通过只能证明受控输入下的软件行为，不等于第三方源或实盘行情质量已获保证。

前端回归还覆盖日线源优先、接口失败提示、缺失日期不冒充休市日、无效季月输入、参考日线滞后时仍保留较新分钟数据。小时聚合按上午和下午分段，并使用桶内实际首条时间作为标签，避免早盘或尾盘 K 线被非交易时段隐藏。
