# 债券舆情监控 Agent：配置与使用

更新：2026-09-23。适用于当前代码，定位为**只读研究情报系统**，不下单、不调整策略仓位、不发布模型。

## 1. 现在可以做什么

```text
东方财富快讯 + 央行新闻 + 央行公开市场公告 + 财政部债券公告
  → 限量采集 / 独立游标 / 源健康
  → 原文与不可变修订版本
  → 事实状态、数值证据、实体、期限、保守方向判断
  → 可选语义解释（JSON约束，无工具权限）
  → 事件关联 / 多个监控订阅
  → 前端证据卡片 + JSON/Markdown简报 + 通知发件箱
```

- 区分 `asserted`（原文明确陈述，**不等于已独立证实**）、`denied`、`rumor`、`conditional`、`historical`、`mixed`、`unknown`。
- “暂无降息计划”“降准传闻”“预计降息”等不再直接形成宽松/利好结论。混合或复杂语义默认弃权；规则并非完整中文理解模型。
- 金额、比例、期限等保留原文片段和字符位置；位置相对 `标题 + 换行 + 正文`，不凭模型生成数值。
- 信用债违约、展期、未按期兑付单独标注为 `CREDIT_BOND` 风险，不转换成 TL 买卖方向。单纯出现“通胀”“增发”也不直接认定利空。
- 官方采集器验证域名、HTTPS、响应类型、大小与重定向；`primary_source` 只表示来自官方原文，不保证所有经济判断为真。
- 同链接正文变更保存新版本及 `revision_of`，不覆盖旧文档。历史查询在新版本实际收到且分析完成后才替换旧版本，不回填“当时已经知道”。
- 不同来源只有在“日期 + 单一主体 + 单一动作 + 明确数值”足够一致时才保守关联；同一文档的澄清沿原事件跟踪。**尚不自动判定任意跨文章传闻与辟谣为同一事件，也没有全网事实核查能力。**

## 2. 直接运行

在仓库根目录执行：

```bash
# 抓取一次；明确禁用外部模型，默认不外发通知
.venv/bin/python src/main.py --mode monitor --no-llm

# 持续运行：默认10分钟一轮，Ctrl+C停止
.venv/bin/python src/main.py --mode monitor --watch --no-llm

# 自定义配置、轮询间隔
.venv/bin/python src/main.py --mode monitor --watch \
  --monitor-config config/bond_monitor.json --interval-seconds 600
```

配置文件是 `config/bond_monitor.json`。CLI、Dashboard 和 ResearchAgent 共用这个配置；运行中的 `--watch` 进程在启动时读取，修改后需要重启。

无模型 release 时仍可独立运行 monitor，不需要训练。打开 Dashboard 不等于启动后台监控；持续采集需要 `--watch` 或现有调度器，两者选择一个，避免重复启动。

前端：**AI决策融合 → 舆情监控 Agent**。

1. 展开“配置订阅主题 / 发行人 / 数据源”，编辑并校验保存。
2. 点击“立即抓取一次”。
3. 按订阅筛选证据，展开原文、出处、事实状态、期限和修订关系。
4. 查看通知投递记录，下载 Markdown 简报。

## 3. 如何监控某个发行人

默认配置包含“利率债与货币政策”“信用债风险”两项订阅。可将 `tasks` 改为：

```json
[
  {
    "id": "issuer-watch",
    "name": "指定发行人信用风险",
    "topics": ["credit"],
    "entities": ["发行人全称", "发行人简称", "债券代码"],
    "keywords": ["违约", "展期", "兑付", "评级"],
    "exclude_keywords": ["历史回顾"],
    "min_severity": "medium",
    "notify_unverified": false
  }
]
```

以上是占位例子，使用前替换发行人及代码。`topics`、`entities`、`keywords` 组间为 AND，组内为 OR；空的 entities/keywords 表示不限制。exclude_keywords 任意命中即排除。

主题：`rates` 利率债、`liquidity` 货币与流动性、`supply` 债券供给、`credit` 信用风险。自定义实体也会加入东方财富采集筛选。最多20个订阅，ID必须唯一。对于数据库里已有事件，新配置会重新匹配展示和通知，不需要重爬。

注意：配置发行人只意味着在**当前覆盖的数据源**中筛选它，不意味着已接入该发行人的所有公告。交易所信用债披露、交易商协会、评级机构及商业资讯授权源尚需另接 provider；微博、公众号、雪球等登录或授权平台尚未接入，不绕过登录/反爬机制。

## 4. 可选模型分析

默认 `semantic_mode: "off"`，规则路径无需模型凭据。

启用前安装 requirements 中的 `openai` 依赖，并在**启动进程的环境**配置 `DEEPSEEK_API_KEY`；配置中设置 `semantic_mode: "online"`。模型名可用 `DEEPSEEK_MODEL` 指定。不要把 API key 写进监控 JSON。当前入口不自动读取 Dashboard 手工填写的 session key 或 `.env` 作为这个语义分析器的凭据。

- 每轮最多 `semantic_max_calls_per_run` 次，默认10、上限50，单次20秒超时，不自动重试收费请求。
- 仅对匹配订阅的非隔离文本调用；模型无工具、交易、网络搜索或执行权限。
- 输出必须符合固定 JSON 字段；证据必须是原文连续引文；新增数字拒绝入库。
- 模型只能进一步降低确定性，不能将规则识别的否认/传闻提升为已发生事实，也不能改写数值事实或交易方向。
- 模型解读仍可能出错，界面明确标注“未经独立核实”。失败保留规则结果，并标记降级；预算用尽记录 `budget_exhausted`，后续轮询继续处理暂缓项，不在同轮无限调用。后来才开启模型不会自动把全部已完成的规则评估送去收费重跑。
- `--no-llm` 在 monitor 中同时关闭语义分析和 Jev；ResearchAgent 的同名选项也关闭新建监控实例的模型调用。

这是有确定性执行边界的 Agent 工作流，不是让模型自由浏览全网或自主调用交易工具。实现参考了结构化文本解析的分工原则：可验证字段由程序处理，自由文本解释交给受约束模型。

## 5. 通知与重试

默认 `notification_channel: "local"`，记录本地订阅通知，不向外部群组发送。

接入飞书自定义机器人：

1. 自行创建目标群机器人的 webhook，并按飞书配置安全校验。
2. 通过安全的进程环境设置 `BOND_MONITOR_FEISHU_WEBHOOK`；启用签名校验时再设置 `BOND_MONITOR_FEISHU_SECRET`。不要把真实值提交到 Git 或复制到报告。
3. 修改 `notification_channel` 为 `feishu`。
4. 显式允许外发：

```bash
.venv/bin/python src/main.py --mode monitor --watch --notify --no-llm
```

也可以在界面勾选“本次允许发送已配置的飞书通知”，再手动抓取。**只有配置、没有 `--notify`/界面勾选时，飞书消息保持 pending，不会发送。** ResearchAgent 和默认 cron 不会打开外发权限。

规则：

- 发布日期缺失、在未来或超过 `alert_max_age_hours`（默认24小时）的内容只作历史证据，不产生订阅通知。旧版的本地事件告警仍是研究风险列表，包含历史事件，不等同于实时通知。
- 传闻、预测、混合、未知状态默认不通知；官方发行计划可以作为计划通知。`notify_unverified: true` 允许这些状态通过，但仍须达到 `min_severity`，低等级传闻还需将阈值设为 `low`。普通媒体的明确报道可通知，但必须带“尚未独立核实”标记。
- 相同订阅、渠道、事件和实质内容只入队一次；事实状态或官方出处等实质变化可以产生更新通知。
- 待发送消息在发送前检查时效、订阅和是否被更正，失效项取消。
- SQLite租约避免同时领取；失败指数退避，最多5次。达到上限保留 failed 记录并报告 exhausted，由操作人检查凭据或网络，不无限重发。
- `local` = 本地落账，`sent` = 外部接口确认接收，`failed` = 失败，`cancelled` = 过期/被更新/不再匹配。消息包含稳定跟踪编号。
- 飞书 webhook 没有本系统可依赖的严格幂等保证。若发送成功后本地未记账就崩溃，重试**可能重复投递**；不宣称 exactly-once。

参考：[飞书自定义机器人官方文档](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)。本轮仅用模拟传输验证接口成功/失败、签名、重试和权限，不向真实群发消息。

## 6. 数据、限制与运维

| 位置 | 用途 |
|---|---|
| `config/bond_monitor.json` | 无密钥的监控配置 |
| `data/intelligence/events.sqlite` | 原文修订、评估、告警、游标、通知发件箱 |
| `outputs/intelligence/<run_id>.json` | 本轮统计、最近事件证据、通知状态 |
| `outputs/intelligence/<run_id>.md` | 最近最多200条评估的订阅简报，不是全量历史导出 |

首次打开旧版数据库会在事务内迁移文档唯一约束，保留原主键和引用。已启用来源的旧v1规则评估在下一次成功/部分成功轮询中按v2重新分析；旧评估保留，时点查询只在新评估完成后使用它。正式环境升级前仍建议备份数据库。通知恢复扫描最近最多1000条文档的最新评估；超出这个规模的长时间停机恢复、全量历史补采、归档与容量治理尚未实现。

四个源都是轮询来源，不承诺交易级低延迟、全量覆盖或服务 SLA。东方财富重读接口的有界近期窗口，以发现迟到内容和更正；接口窗口之外的停机缺口无法补齐。每个官方源每轮最多10篇正文，优先未见条目，再轮换复查当前列表；不自动翻页做历史全站爬取。部分文章失败或列表积压会明确降级，不会伪装完整成功。

官方列表只有日期时保存 `publication_precision=day`；具体首次可用时间以本系统收到正文为准。休市/节假日及低频财政公告可能触发72小时无新增提示，应结合来源更新频率解释，不将其直接解释为网站故障。

原文有长度上限，列表结构变化、访问限制、缺少正文都会显式报错；不会执行网页脚本、绕过验证码或访问任意用户指定站点。
